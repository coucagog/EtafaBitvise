Faisabilité d'un client SSH multiplateforme

Rust + Vite, pour Windows, Linux, macOS et Android · référence Bitvise SSH Client 9.66 · 8 novembre 2026

Verdict : le cœur SSH en Rust fonctionne sous Windows (18 tests réussis sur 19) et sur une vraie tablette Android (16 sur 17 dans l'application).

Le client russh ne bloque pas face à un vrai serveur OpenSSH : 33 essais réussis sur 33 en trafic intense dans les deux sens, dont 22 à pleine vitesse. Les blocages relevés sur le banc n'apparaissent qu'avec notre serveur russh de test ; ils ne concernent pas l'usage prévu, un client russh face à de vrais serveurs.

Une APK Tauri + Vite de test tourne sur la tablette. Linux et macOS n'ont pas été compilés, et l'interface réelle reste à construire.

Limites de compatibilité avec Bitvise

  • Profils .tlp : aucun format publié trouvé, import non prévu.
  • Obfuscation Bitvise : aucune spécification publique trouvée, compatibilité non garantie.
  • Panneau de contrôle serveur et règles centralisées : propres à Bitvise SSH Server, exclus.
  • bvterm : spécification publique de 2010, basse priorité.
  • mlkem1024nistp384 et sntrup761 : absents de russh 0.65.1 ; mlkem768x25519 reste disponible.

Canal unique : seule la file du serveur russh de test compte. L'agrandir supprime le blocage ; agrandir celle du client n'y change rien. La boucle de session russh attend quand la file d'un canal est pleine (server/encrypted.rs:1514). Le relais de test vers le service d'écho pourrait alors former un cycle d'attente avec elle : ce cycle est déduit du code, pas observé directement. Ce blocage concerne le serveur de test, pas notre client.

Nombreux canaux : seul le relais réseau supprime le blocage. Les deux extrémités semblent donc s'arrêter sur l'écriture réseau sans plus lire. Le client russh y participe et notre application l'utilisera.

Conclusion : les mêmes cas, dont ceux qui bloquaient toujours contre notre serveur russh, passent tous contre OpenSSH. Le blocage tient donc à l'appariement avec le serveur russh de test.

Limites : ce test ne porte que sur OpenSSH. Il n'a pas été refait depuis Android, ni contre un serveur Bitvise. Le blocage de l'APK à 64 canaux a été observé uniquement contre le serveur russh embarqué dans l'application de test.

Limites : le client n'a pas encore été confronté à un vrai serveur OpenSSH ou Bitvise. La reconnexion automatique, les files de transfert et le miroir restent à écrire. Détails : journal-dev/.
